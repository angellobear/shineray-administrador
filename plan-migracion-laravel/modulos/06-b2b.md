# Módulo: B2B (clientes, políticas de crédito, transportistas)

## Referencia en `medusa-shineray`

- `src/models/client_b2b.ts`, `policies_b2b.ts`, `transportistas_b2b.ts` —
  definición de columnas (ver `02-modelo-datos.md` para el mapeo exacto,
  incluyendo las FKs que hoy NO existen y se agregan en Laravel).
- `src/repositories/client_b2b.ts`, `policiesb2b.ts`, `transportistas_b2b.ts`
  — patrón `dataSource.getRepository()` fuera de Awilix; no hay lógica propia
  que portar más allá del acceso a la tabla.
- `src/api/store/client-b2b-verify/index.ts` — crea/verifica el `Customer`
  asociado a un cliente B2B. **Contiene un hash de password fijo
  hardcodeado** (`shineray2024`) usado para todo cliente B2B autocreado —
  **no portar el hardcode**; ver `modulos/11-auth-seguridad.md` para la
  estrategia de reemplazo (ej. invitación con set-password individual).
- `src/api/store/get-address/index.ts`, `get-cuota-b2b/index.ts`,
  `get-transportistas-b2b/index.ts`, `valor-deuda-credito/index.ts`,
  `recommended-products-b2b/index.ts` — endpoints de consulta B2B para el
  storefront. Todos hoy fuerzan `Access-Control-Allow-Origin: *` manualmente
  — **no portar el CORS abierto**, ver `modulos/11-auth-seguridad.md`.
- `src/jobs/sync-clients-b2b.ts`, `sync-policies-b2b.ts`,
  `sync-transportistas-b2b.ts` + sus rutas HTTP gemelas en
  `src/api/store/sync-*-b2b/index.ts` — ver `modulos/09-erp-sync.md` para el
  detalle de sync (incluye los bugs de atomicidad a corregir).
- `src/services/credito-b2b-payment-processor.ts` — el "pago" a crédito B2B
  (sin pasarela externa) — ver `modulos/04-pagos.md`.

## Esquema de datos

`client_b2b`, `policies_b2b`, `transportistas_b2b`, y la relación con
`customers` — ver `02-modelo-datos.md`. Diferencia clave respecto a hoy:
`client_b2b.customer_id` y `policies_b2b.client_b2b_id` son FKs reales, no
strings sueltos vinculados en runtime.

## Diseño en Laravel

- `app/Domain/B2b/Models/ClientB2b.php`, `PolicyB2b.php`,
  `TransportistaB2b.php` con relaciones Eloquent reales
  (`ClientB2b::hasOne(PolicyB2b::class)`, `belongsTo(Customer::class)`).
- Endpoints de consulta B2B protegidos con Sanctum (guard `customer`) en vez
  de CORS abierto sin auth — un cliente B2B debe estar autenticado para
  consultar su propia dirección/cuota/deuda. Ver `modulos/11-auth-seguridad.md`.
- El flujo de "verificar/crear cliente B2B" se modela como
  `app/Domain/B2b/Services/ClientB2bVerificationService.php`, que internamente
  usa el `ErpClientContract` (no un cliente HTTP ad-hoc) para consultar al
  ERP si el cliente ya existe.
